{%- comment -%} Renders jekyll-seo-tag, overriding the title and meta description where a page supplies its own. Resolution order, most specific first: 1. the page's own `seo:` front matter block 2. the `seo:` block in the data file named after the page's permalink (/hours -> _data/hours.yml, /gift-cards -> _data/gift-cards.yml). Data files are deliberately named to match, so no per-page declaration is needed. 3. a per-collection title formula, and `subtitle` as the description for items whose body is empty 4. plain {% seo %} — the plugin's default output jekyll-seo-tag offers no hook for a raw per-page title: `Drop#title` always appends `" | " + site.title`, and og:title/twitter:title are hardwired to `page_title`. So the tag is rendered into a string and the generated values are swapped out. Every value swapped here is rebuilt from the same inputs the plugin uses, so the match is exact: page_title = page.title | default: site.title description = page.description || page.excerpt || site.description Both are stripped before use: a value that is only whitespace is truthy to Liquid but empty to the plugin, which would make the search string "" and the swap a no-op. This is why Gemfile pins jekyll-seo-tag: if a future version changes its output markup, these swaps silently no-op instead of failing the build. {%- endcomment -%} {%- comment -%} 1-2. explicit override: page front matter, else its data file. {%- endcomment -%} {%- assign seo_block = page.seo -%} {%- if seo_block == nil -%} {%- assign seo_path = page.url | remove: "index.html" | remove_first: "/" -%} {%- comment -%} Top-level pages only: matching the whole path means a nested URL such as /events/cinco-de-mayo/ can never be hijacked by a same-named data file. {%- endcomment -%} {%- assign seo_depth = seo_path | split: "/" | size -%} {%- assign seo_key = seo_path | remove: "/" -%} {%- if seo_key != "" and seo_depth == 1 -%} {%- assign seo_block = site.data[seo_key].seo -%} {%- endif -%} {%- endif -%} {%- assign seo_title = seo_block.title | strip -%} {%- assign seo_desc = seo_block.description | strip -%} {%- comment -%} 3. collection fallbacks, only where no explicit value was given. {%- endcomment -%} {%- if page.collection -%} {%- if seo_title == "" or seo_title == nil -%} {%- case page.collection -%} {%- when "shops", "galleries", "foods", "events" -%} {%- capture seo_title -%}{{ page.title }} in Sedona, AZ | {{ site.title }}{%- endcapture -%} {%- when "blogs", "articles", "wedding-articles" -%} {%- capture seo_title -%}{{ page.title }} | {{ site.title }} Sedona{%- endcapture -%} {%- endcase -%} {%- endif -%} {%- comment -%} Collection items must describe themselves, not the village.
